# Contributing to the AI SEO Implementation Checklist

Thank you for your interest in improving this resource.

This repository contains practical documentation covering technical SEO, AI search, structured data, entity optimization, content optimization, internal linking, and SEO measurement.

Contributions that improve the accuracy, clarity, usefulness, and maintainability of the documentation are welcome.

---

## 1. What You Can Contribute

Useful contributions may include:

- Technical corrections
- Documentation improvements
- Clearer explanations
- Typo and grammar fixes
- Better examples
- Improved implementation steps
- Additional troubleshooting guidance
- Corrections to outdated information
- Useful checklists
- Clarifications of confusing concepts
- Evidence-based improvements
- Documentation of legitimate implementation experience

Contributions should improve the resource for its intended readers.

---

## 2. Accuracy Comes First

Technical SEO and search systems can change over time.

When proposing a technical change:

- Verify important claims.
- Prefer official documentation when available.
- Identify the relevant platform or standard.
- Avoid unsupported guarantees.
- Distinguish documented facts from interpretation.
- Identify limitations where appropriate.

Do not submit information simply because it appears frequently on other SEO websites.

---

## 3. Sources and Evidence

When a contribution introduces an important factual claim, provide an appropriate source when practical.

Useful sources may include:

- Official search-engine documentation
- Official platform documentation
- Standards organizations
- Government resources
- Academic research
- Original datasets
- First-party technical documentation

Prefer primary sources when they are available and relevant.

Do not fabricate citations, references, experiments, or data.

---

## 4. First-Hand Experience

Practical implementation experience can improve documentation.

If contributing first-hand experience:

- Describe what was actually tested.
- Explain the relevant environment.
- Distinguish observations from conclusions.
- Avoid presenting one site's result as a universal rule.
- Do not claim results that were not measured.

For example:

```text
Observation:
A configuration change was tested on a WordPress website.

Measured result:
The site showed fewer technical errors after the change.

Conclusion:
The change may have contributed to the improvement.

Limitation:
Other changes occurred during the same period.
